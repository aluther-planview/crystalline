# Use the Source, Luke.

Knowledge that comes from somewhere should remember where. An engram now keeps every location it was distilled from, and an agent can find, update and clean them up again. Also: a share never proposes a deletion it did not see.

## New & Noteworthy

**Sources you can keep current.** An agent that ingests notes, a repository or a wiki writes every location into the `sources` list of each engram. Until now it could not change that list later without rewriting the whole engram. Now `edit_engram` `set_frontmatter` takes `sources` like `tags`: read the engram, then pass the whole new list.

- The spelling is kept exactly as you write it, because `$contains` matches it exactly. Blanks are dropped and a repeat is kept once.
- A location longer than the metadata index can hold (1024 bytes of JSON) is refused by its position, so it never lands where a search cannot find it.
- An empty list removes the key.

The capture skill now teaches the whole pattern:

- Put every location into `sources` in one stable spelling, without a version. Keep the pinned one in `resource`.
- On a re-ingest, find the engrams of the changed paths with one `$contains_any` search (up to 100 locations a call) instead of a search by meaning.
- A renamed path is found by its old address and rewritten.
- A location that is gone from the source is removed from `sources`. That alone is no reason to retire the engram.

**Update Crystalline, not the extension.** The Claude Desktop extension only starts the Crystalline you installed, so `brew upgrade crystalline` (or the newest MSI on Windows) is all you need. Should the extension itself ever be too old, your agent tells you.

## Fixes

- A share could fail with "os error 4395" when the domain folder or Crystalline's own folder sat behind a link, a junction or a redirected folder. Worse, it could then list engrams as deleted that you never touched, and a share would have proposed deleting them for the whole team. Now a share never proposes a deletion it did not see: a file it cannot read stops the share and is named, and a link is named with what to do about it. A pull checks every file before it changes one, so a failed pull no longer leaves files missing. Crystalline also removes its own folders without going through a link.
- `config set`, `domain add`, a subscribe, a domain rename and the other settings writes could save over a `config.yaml` that did not parse, and your hand edit was gone. They now refuse and leave the file as it is. A rename, a subscribe or a `domain add` refuses before it changes anything.
- After you signed in to Fluid, an engram you had opened before could still show as read-only, without edit controls, until it changed.
- Fluid and the REST API showed no read-only mark to an anonymous viewer, who can write nowhere.
- `list_domains` had become about four times slower with 0.25.0. It is fast again.
- `configure` with `read_only: on` on a domain that was already read-only answered that only a person can switch it off. It now says the domain is already read-only.
- `crystalline prompt system` did not mark a read-only virtual domain.
- `domain add` on a read-only domain skipped writing the domain name into its MANIFEST without a word. It now says why.
- `users writes` and `users add` printed text with `--json`. They now print JSON, and `users add --json` includes the write list.
- A write-list entry with a 64-character domain name and a `*` was refused.
- A REST write to a domain that does not exist answered with the write-list refusal. It now says the domain does not exist.
- The share preview of a direct share could give a different first reason than the share itself when there were open conflicts.
- A model download filled `daemon.log` with dozens of lines a second.
- The Claude Desktop extension's tool list in Claude Desktop was missing three tools.
- `verify` (rule Q004) and the near-duplicate check of the maintenance sweep could report two sections or engrams as copies when they only used the same words, for example two tables with the same column headers. Both now also need the same words in the same order.

## Changes

- The Claude Desktop bundles have new names: `crystalline-claude-desktop-v0.25.1.mcpb` and `crystalline-claude-desktop-only-v0.25.1-macos.mcpb` (the one that carries Crystalline inside).
- A pull now stops, with the file named, when a file it must change is read-only or a folder stands where the team has a file.
- On a Mac or on Windows, a pull or a share now stops when the team repository holds two files whose names differ only in letter case (for example `A.md` and `a.md`). This computer keeps them as one file, so Crystalline can't tell what changed. Before, a pull could remove that one file and a share could then propose deleting the other. Give both files new names in the team repository, from a computer that can hold both, and try again.
- A read-only answer from `GET /domains/{domain}/engrams/{permalink}` has its own ETag (it ends in `-ro`), and the answer varies by who asks. A write with that ETag in `If-Match` still works.

## Breaking changes

None.
