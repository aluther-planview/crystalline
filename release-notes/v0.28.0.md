# Show me.

Pages for people get the tools a wiki has: callouts, status labels, diagrams, math, task lists and more. The editor helps you insert them, and agents learn when to use them.

## New & Noteworthy

**Markdown that does more.** People who come from a wiki missed a few things. They are here now, and every one of them still reads fine as plain Markdown (on GitHub too). The full reference is [docs/markdown.md](https://github.com/jordiboehme/crystalline/blob/main/docs/markdown.md).

- Callouts: `> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]` and the neutral `[!DETAILS]`. A title goes on the same line (`> [!WARNING] Data loss`).
- Expand blocks: a fold sign after the kind folds a callout. `-` starts closed, `+` starts open. `> [!DETAILS]` folds closed on its own. A link or a comment inside a folded block opens it.
- Status labels for tables and text: `:status[In review]{blue}`. Six colours: grey, blue, green, yellow, red and purple.
- Math: `` $`a^2 + b^2`$ `` inline, `$$ ... $$` or a `math` fence for blocks. A single `$` stays a dollar sign, so "costs $5 and $10" is still text.
- Task lists you can tick on the reading page, if you may edit it. `- [~]` marks an item as not applicable.
- Footnotes with links both ways, a Copy button on code blocks and a small swatch next to a colour code like `` `#0969DA` ``.
- Long pages get "On this page": an outline in the right column that shows where you are.
- Every diagram type the editor offers now renders well in light, in dark, on a phone and on paper.

**One editor for engrams and Reflection pages.** The Reflection editor had one button (Attach). Now it has everything the engram editor has, from the same code: formatting, headings, lists, tables, diagrams and code. The hidden section ids stay safe under every command, also while others type in the same page.

- One Insert menu holds callouts, expand blocks, status labels, diagrams, code, math and footnotes. Type `/` at the start of an empty line to get the same list (plus tables and task lists) right where you write.
- Put the cursor into a callout and the toolbar offers its kind and whether it folds. In a status label it offers the six colours.
- Callouts, labels, swatches and math show as they will on the page, except on the line you are typing in.
- The menus of Fluid share one look now.

**Paste from other apps.** Copy a page from a wiki, a web page or a word processor and paste it. Fluid turns it into clean Markdown: headings, lists, tables, links, info panels as callouts, expand blocks as folded callouts and status lozenges as status labels. Scripts, styles and unsafe links are dropped. Cmd-Shift-V (Ctrl-Shift-V) pastes plain text as before.

**Agents present, not just write.** Agents wrote pages for people like notes for themselves. A new shipped skill, `crystalline-presentation`, teaches them better. A protocol between parties gets a sequence diagram. A comparison gets a table. A risky step gets a warning right where it happens. Everything else stays prose: an element is there to explain, not to decorate. A new PACT starts with a Presentation section, and what it says wins over the skill. Agents that reach Crystalline only over MCP read the skill with the `skills` tool. Existing installs get the skill with the next session start. In our benchmark the skill passed two of three test pages, against none without it.

**Comments that say what they want.** Agents already write every thread comment as a [conventional comment](https://conventionalcomments.org): a label like question or issue, then the subject. Now people get help with it too. The comment box and the answer box have a Label menu with the nine labels and one line on what each means. Pick blocking, non-blocking or if-minor after it. You can also type `issue (blocking): ` at the start, and it turns into a chip. A label is optional, and the comment is stored as plain text like before. Threads show the label as a small pill with the subject in bold. Only blocking is red. A "Blocking only" switch shows only the blocking threads. Agents see the label in the `reflect` queue and answer blocking threads first. How it works is in [docs/reflection.md](https://github.com/jordiboehme/crystalline/blob/main/docs/reflection.md).

**Reflection pages across domains.** One page can now give an overview of several domains. Name a source in another domain by its address, for example `crystalline://ops/runbooks/deploy`. The queue then tells the agent when that engram changes, is retired or is gone.

- People only see sources in domains they may open. Everyone else sees a count, for example "2 sources in a domain you cannot open".
- When a domain is not on this server, its sources say they cannot be checked here. They are never reported as missing, so no agent drops them by mistake. A curator who can see such a source can still remove it.
- A source names its domain and links there, if that domain is on this server.
- `crystalline domain rename` renames the domain in the sources of every page too. So rename a domain with it, not by hand in the MANIFEST.
- Did an agent keep sources from another domain in HTML comments so far? Ask it to move them into `sources`. Then the queue watches them.

**Lints for the new Markdown.** Q006 flags an unknown status colour, Q007 an unknown callout kind and Q008 an observation, relation or quote inside a callout (it is not indexed there). Agents see them in the answer of a write (`markdown_findings`). `crystalline verify` reports them too, and the engram editor shows them with the other findings.

## Fixes

- Footnote links in Fluid did not jump anywhere: the target of the link was dropped. They work now, also when two sections of a Reflection page both use `[^1]`.
- In the Reflection editor, typing or pasting right at a hidden section id could write into it. The section lost its id, and its threads lost their anchor. The id line is out of reach now.
- After an agent wrote a Reflection page with an intro, the next `reflect` listed that intro as a person's change. The agent then worked on its own text again. Now an agent's fresh text is settled with its write. A person's change is never settled that way.
- A Reflection write to a path that started with `reflections/` put the page into `reflections/reflections/`. Such a path is refused now, and the answer names the right one. An existing nested page can still be read and moved out.
- Sources keyed by a heading that two sections share went to the first one without a word. They are refused now. The answer names both headings and says to use the section id.
- In dark mode some diagram types were hard to read: the mindmap root, the git graph branch labels and the C4 relationship text and lines. They use the theme's colours now.
- An agent answered a person's question in a Reflection thread and resolved the thread in the same step. Fluid hides resolved threads, so the question looked unanswered and the answer was hidden. Now an agent answers and leaves the thread open, and the person who opened it resolves it. Fluid shows "Answered, waiting for you" on such a thread.
- HTML comments like `<!-- sources: ... -->` showed on the page as text. Fluid does not show them anymore. They stay in the file, and the editor shows them on the line you edit.
- A comment or a page change that another program wrote to the files showed only after a reload. Now the open page updates. The event stream also opens at once. Before, a proxy could hold it back for up to 15 seconds. After a lost connection, Fluid loads the data again.
- On a phone, the details of an engram showed several times.
- A comment's quote could be a letter or two short after you selected the text with the keyboard.
- Printing from Safari in a wide window put the page into a narrow column. Every page prints full width now. A heading stays with its text on paper, and short tables, callouts and code blocks are not split.

## Changes

- Task list items (`- [ ]`, `- [x]`) are no longer read as observations, and a bullet that starts with `:` or `[` is no longer a relation. Existing indexes parse again once on their next sync, by themselves.
- Ticking a task box on a Reflection page is not a change the agent has to weigh. It does not show up in the reflect queue.
- `reflect` refuses arguments it does not take and points to `write_reflection` for settling.
- `write_reflection` refuses a sources key it cannot place (the `#` title, a `###` heading, an id the page does not have) and lists the headings the page has. A key may carry its `## ` marks.
- `write_reflection` with only `sources` and no text curates the sections as the page stands.
- A write that removes a section with a person's pending change still goes through, and its answer names that section.
- Opening a thread by a heading that two sections share is refused. Use the section id.
- An id an agent copies from another page is replaced, and the answer says so. The `reflection:` frontmatter is Crystalline's own: agents pass `sources` instead.
- Citing a domain the writer may not open, an unknown domain or one a connected server serves is refused, with the same words for all three.
- An agent that tries to resolve a thread a person opened, while the last word is its own, gets a refusal. People can resolve any thread as before.
- Seven skills ship now, and six are installed into harnesses. `crystalline install` and `crystalline doctor` know the new one.
- Fluid moved "Insert diagram" and "Insert code block" into the Insert menu. Fluid has no public UI contract, but a script that clicks by name may need an update.
- For scripts that read the Reflection API: a source can now carry a `domain`, and a section can carry `hidden_sources` (a count). A source has a new state `unavailable`, and the queue has a new item `source_unavailable`. Thread items carry `label` and `blocking`.
- The Reflection backup branch and the domain archive keep the pages as they are. So they also show the names of other domains a page cites.

## Breaking changes

- `crystalline verify --strict` fails on warnings. Q006 and Q007 are new warnings, so a domain that passed with 0.27.0 can fail now. Fix the status colour or the callout kind it names.
