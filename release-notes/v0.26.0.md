# Mirror, mirror

Your agent now writes for people too: a domain can have a Reflection, pages a person reads, edits and comments on, and the agent keeps them true to what it knows.

## New & Noteworthy

**Reflection.** Engrams are written for agents. They are short, linked and full of detail a person doesn't want to dig through. The people around the agent need something else: a handbook page, an onboarding guide, a "how we deploy" they can read in five minutes. Until now somebody had to write those by hand and keep them in sync. Now the agent does it. Switch it on in the domain policies (`reflection: on`), and the folder `reflections/` holds pages the agent writes from the domain's engrams.

- People edit a page like any Markdown file. The agent sees each change as feedback: it takes it into the engrams, keeps the person's words or asks back.
- Every `##` section gets a hidden id. A section remembers which engrams it was built from, so the agent notices when one of them changes.
- `reflections/PACT.md` is the agreement between people and agent: what the pages are for, who reads them and how the folder is organized.
- The Reflection stays out of everything engram: sync, the index, evolve, engram search and share changes. Engram tools refuse paths under it.
- Switching it on is refused while engrams still live in `reflections/`. The answer names them, so you move them first. Nothing is dropped on upgrade: with the switch off, `reflections/` is an ordinary folder.

**Four new tools.** `reflect` is the agent's work queue: feedback from people, sections whose engrams changed, open comments. Oldest first, with its age. `read_reflection` shows the tree or one page. `write_reflection` writes pages and sections and has the same section operations as `edit_engram`. `discuss` opens, answers, resolves and reopens comment threads. The tool list grows from 20 to 24.

**Search in a Reflection.** `read_reflection` takes a `query` and answers the sections that match, with a snippet. It searches by words, by meaning or both (the default). When the pages are not embedded yet, it searches by words. Engram search leaves the pages out, so the agent asks `read_reflection` for them.

**Comments.** A thread sits on a section or on a quoted passage. When a rewrite removes the passage, the thread stays on its section and says the text changed. Threads are plain Markdown files beside the page, readable in any file browser. Agents write their comments the conventional-comments way (`suggestion: ...`, `question: ...`).

**Two kinds of access.** Knowledge and Reflection are now set side by side. Knowledge gets a new level, `none`: the person sees no engrams at all. The Reflection level is one of two:

- Reader: reads pages and comments on them.
- Contributor: also edits pages and creates, moves and deletes them.

Everyone who may edit the engrams also curates: settles feedback, writes `PACT.md` and records which engrams a section was built from. So a colleague can read and improve the team handbook without ever seeing the engrams behind it. An account with a write list can at most read and comment on the Reflection of a domain that is not on its list.

**One home, one backup.** A domain shared through GitHub has exactly one home for its Reflection: the team server. `reflection_home` in the MANIFEST holds its address, filled in when you switch on there. Any other instance answers with a link to the home. The home backs the whole folder up to the branch `crystalline/reflections` of the domain's repository. The engram branch never carries it. Careful with the switch: while it is off, `reflections/` is ordinary engram content again, and share changes offers it. Don't share while it is off.

**Nudges.** When a domain of your session has open Reflection work, the write result, the Stop hook and the session start say so.

**Images and files in pages.** Pages carry attachments like engrams do, in `reflections/assets/`. A Reflection reader sees every image of a page, also without access to the engrams. Moves rewrite the links, the backup and the export carry the files.

**What's next.** Fluid gets its Reflection mode in the next release: the page tree, live co-editing, comments on selected text and a review screen. The REST API and the live editing socket it builds on are in this release. Until then people reach the Reflection through their agent, the files on disk and the REST API. `docs/reflection.md` explains it all, with a daily agent run that works the `reflect` queue.

## Fixes

- A search with a non-ASCII letter in a different case (`Ü` for `ü`) found the engram but showed the start of it instead of the match.
- `doctor` listed the files of an artifact folder as unindexed engrams, and its stray-copy check looked into artifact folders.
- `doctor` listed Markdown files under `assets/` as unindexed engrams. The sync never indexes them.

## Changes

- MCP clients see four more tools (24 instead of 20; 11 of them are read-only).
- The index is upgraded on the first start. An older Crystalline refuses the upgraded index.
- The REST API's role and member level types gain `none`, and the user shape gains `reflection`. `crystalline users add --json` prints it too.
- Renaming a domain also respells its name in Reflection pages.
- The domain policies have two more rows, `reflection` and `reflection_home`.
- `crystalline status` counts the Reflection's text chunks in the embedding backlog, beside the engram chunks.
- Fluid does not offer the knowledge level `none` or the Reflection level yet. Set them with `crystalline users`, `crystalline domain members` or the REST API.

## Breaking changes

None for an upgrade. Before a downgrade, take care: an older Crystalline reads the knowledge level `none` as viewer. After a downgrade an account at `none` can read every shared domain, and a member at `none` its private domain. The older version also drops the Reflection level of a membership it rewrites. So before a downgrade, set every account and member at `none` to a level that fits the older version, or disable or remove them. `crystalline users list` and `crystalline domain members <domain> list` show them.
